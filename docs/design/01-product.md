# 01 产品定义

## 1. 要解决的断点

dsh(以及 Claude Code / Codex)现在的工作单位是**会话**——所有状态(计划、待办、目标、上下文)活在会话里,会话结束,主动性就死。四类具体断点:

1. **跨时间**:任务做三天,每天新会话,模型每次失忆;
2. **跨项目**:一个功能动三个仓库,三个会话互不知晓;
3. **跨窗口/设备**:能带走日志文件,带不走"进行中的工作";
4. **跨执行者**:人与子 agent 分头做,谁也不知道整体进度。

记忆(AGENTS.md)解决"知识跨会话",不解决"工作跨会话"——两个不同的产品问题。

## 2. 定位

三个候选:连续性(记忆导向)/ 编排(管理导向)/ 协作(团队导向)。

**结论:连续性为主、编排为辅、协作不做。** 连续性是四类断点的公共解;编排(看板)搭连续性的便车,近乎免费;协作会引入身份、权限、冲突合并,把产品拖重。

产品的用户有两个——**人和模型**。任务数据要同时满足"人能看懂、能管理"与"模型能消费、能恢复上下文"。

## 3. 锚定场景(功能设计的检验标准)

1. **并行看管**:5 个任务同时在场,面板一眼看全;阻塞项置顶等我介入;
2. **跨会话续命**:任务做了一周换了 8 次会话,第 9 次认领时模型不需要人复述背景;
3. **定时干活**:睡前挂"每天早 9 点检查依赖更新",次日看结果,人不在场。

## 4. 形态

**宿主内的一族插件,三个面:**

- **人类面(主)**:任务面板——全景、阻塞告警、待验收队列、执行记录跳转;
- **模型面(主动性来源)**:认领、读上下文包、推进、汇报、报阻塞——面板状态靠它自己动;
- **时间面(长期干活引擎)**:任务挂唤醒规则,到点起新会话认领续干。

一句话:**面板负责"看见",工具负责"推进",闹钟负责"活着"。**

## 5. 与现有概念的分界

| 概念 | 归属 | 与任务的关系 |
|---|---|---|
| goal | 会话内目标(事件投影) | 细粒度,会话死即止;任务是会话外容器,**不取代** |
| todo | 会话内待办 | 同上 |
| AGENTS.md / persona | 知识层记忆 | 跨会话的是"知识";任务管"工作"——互补 |
| session | 一次执行 | 降级为任务的子对象:任务 = N 次会话的父容器 |
| workspace | 工作区登记 | 任务挂工作区 id;可见性沿用其授权思路 |

## 6. 产品纪律(不是功能缺失)

- **待验收必须人确认**——不追求全自动,经理可以放手,不能没有签收权;
- 打回必须附理由,理由进上下文包(下次认领时模型看得到);
- 一期不做:多人协作与权限、通用笔记/知识库、自动冲突合并(跨设备一期策略:后写覆盖、历史可查)、取代 goal/todo。
