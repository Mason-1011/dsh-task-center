# 06 抽取层:任务从已有记录出生

状态:已定稿;实现中——片 6a 已落地(2026-08-18,见 §9 切分表),6b 起按表推进。前置判断:任务不应该是独立于 plan / goal / 普通对话之外的东西,而应能从 dsh 已有的功能与记录中抽取;抽取要自动化、无感,同时要有严格的"什么是任务"判据防噪声。

## 1. 问题:出生通道与原始记录脱节

现状里任务只有两条出生通道,都要人驱动:`/task create`(人类面)与 `task_create`(模型面)。而 dsh 会话日志里**已经**记着任务形状的东西:

| dsh 已有记录 | 事件 | 内容 | 缺什么 |
|---|---|---|---|
| goal(目标) | `goal/change`,全量快照 | objective、phase(active/paused/blocked/complete)、blocker、轮次 | 跨会话;验收标准;人的裁决 |
| plan(计划模式) | `exit_plan_mode` 工具调用,必填 `plan` 参数 | **完整计划 markdown,以 # 标题开头**;经人类精确批准 | 跨会话;验收标准同款 |
| todo(待办) | `todo/write`,整表快照 | 步骤文本 + 三态勾选;可锚定到触发它的人类消息 | 目标级视角;一切跨会话字段 |
| 普通对话 | `user/message` 等 | 用户说过的每一句"要做 X" | 一切结构 |

这些记录的共同点:**只属于单个会话,会话停了就停在那里,没有机制负责跨会话追问**。而"被遗忘"恰恰发生在人离开之后。登记是纪律,纪律靠不住,台账于是常年是空的,看管价值无从发生。仓库已有一次性先例 `c86ba75`(cc-transcript 导入);本设计把它一般化为**常驻、自动、无感的抽取**。

## 2. 任务的抽取判据(防噪声的定义)

抽取自动化的前提是判据严格。一条记录要成为候选,必须**同时**满足三必要条件:

1. **可命名的结果**:能用一句话说出"做成之后世界里多了什么"。objective 是**结果**不是动作("支持暗色模式"✓,"看看暗色模式"✗)。
2. **可判定的完成**:能写出验收标准 —— 一条事后可检查的判据。写不出完成判据的(纯讨论、开放探索、感受表达)不是任务。
3. **未完成且需要后续工作**:本会话内已做完、已回答的,不抽。做完的事是历史,不是任务。

结构档(goal / 已批计划 / todo 链)天然满足三条件:goal 创建即带 objective、未完 phase;计划有标题与步骤且经人批准;todo 链锚定的是用户原话。**总结档(模型抽取)必须三条全填才准产候选:objective、acceptance 都要写得出,acceptance 填不出 → 返回"无任务"。宁缺毋滥。**

反例与正例(总结档提示词内置):

| 会话里的事 | 判定 |
|---|---|
| "为什么这里报错?" 已解答 | 无任务:已回答 |
| "聊聊这个架构怎么样" | 无任务:无结果命名、无完成判据 |
| "帮我加暗色模式" 没做完 | 任务(objective: 支持暗色模式;acceptance: 切换后全部界面生效) |
| "以后有空把首屏优化一下" | 任务(objective: 首屏 < 1s;acceptance 可写;未做)—— 搁置的意图正是本产品目标 |

去重:总结档在抽取时拿到现有任务与候选的 objective 列表,判定为重复的不产候选(可标注关联既有任务)。

## 3. 原则:两层,各司其职

纯投影(任务完全从会话日志实时算出)不可行:持有者、闲置时钟、唤醒规则、验收裁决是**跨会话事实**,不属于任何会话日志,只读视图装不下它们,也没有地方写回。因此:

```
抽取层(新,读):自动扫描会话 → 派生"候选" → 人确认晋升 → 进台账
台账层(已有,写):状态机 / 持有 / workedAt / 唤醒 / 巡检 / 验收 —— 跨会话唯一权威
```

- 抽取层是投影,不产生权威状态;它的产出只有候选。
- 台账层职责不变,仍以台账为唯一输入(巡检、唤醒、闲置都不读会话日志)。
- `task_create` 定位收窄:只剩干活途中分解父任务一个用途(`parent_task_id`),工具描述随之更新。

## 4. 触发:闲置即抽取(无感)

**主触发:会话静默超过 `idleHours`(默认 3 小时,config 可调)** —— "3 小时没人说话"区分了"人还在,只是去倒杯水"与"这条线被搁下了"。`session/disposed`(会话明确关闭,含 headless 一次性会话)立即触发,不等闲置。

- 活动/水位跟踪:进程内订阅 `session/event` 记每个会话的最后事件时间;重启后从持久化日志做一次启动扫描(task-reaper 同款模式)。闲置时钟锚定到最后一条**持久**事件——水位播种跳过 store 附着日志时补的 `session/end-seed` 簿记标记(附着不是会话活动),恢复的会话开机即可判闲置。
- 幂等:每个会话记录"已抽取水位"(最后抽取时的活动位置)。会话有**新活动**才可能再次抽取;静默着的老会话不重复花钱。
- 每轮 tick 限制总结会话数量(防止开机/久置后突发一堆模型调用),超额顺延;配额墙复用 task-wake 的 probe 推迟模式。
- 结构档(goal/计划/todo)先跑:**零模型成本**;有结构信号就不起总结会话。总结会话只在无结构信号时兜底。

## 5. 候选:新的轻实体族

- **不进任务状态机**。候选动词:`promote`(晋升为任务)、`ignore`(忽略,终态)、`superseded`(自动:来源会话后来把事做完了 —— goal complete / todo 全勾 / 后续对话明确收尾 —— 候选自动标记失效,人仍可翻看)。
- **进台账事件流**(与 projects 同模式的新实体族,同一 fold 聚合返回):重启可恢复、看板可读、与任务同源持久化。
- 记录字段:候选 id、来源(`sessionId` + 事件引用)、objective 草稿、acceptance 草稿(结构档留空由人补)、备注(blocker / 未完 todo / 计划正文)、创建与水位时间。
- **去重(v1 实现)**:去重键是完整来源三元组(sessionId + tier + key);同源候选**任一状态**(含已忽略/已失效)存在即不再产,不刷新时间戳。goal id 跨会话不复用,故跨会话同主题会各产一条——是否升级为跨会话键随开放问题 2 的真实数据定。同会话单候选(见 §10.4)。
- **忽略语义**:同源任一状态即去重 ⇒ 忽略天然对该来源永久;「已忽略后再现」标记随之不需要(未实现;若将来放开同源再现再补)。

## 6. 抽取规则:常驻结构档 + 兜底总结档

同一会话一次抽取至多产出**一条**候选,取结构最全的来源,优先级:**goal > 已批计划 > todo 锚定 Query** —— 三者常是同一件事的三个影子,合并成一条。

**结构·goal(片 6a,零模型成本)**:fold 该会话的 goal;phase 为 active / paused / blocked(非 complete、非已 clear)→ 候选。objective 直取 goal.objective,blocker 写入备注。

**结构·已批计划(片 6b,零模型成本)**:计划全文躺在 `exit_plan_mode` 的必填 `plan` 参数里,批准走 `ctx.userQuestions` 精确批准 —— 不需要模型总结。判定"已批":会话从 `plan/mode` active 翻出且翻转不是 `command/run` 的 `/plan off`(两条路径事件流可区分)。会话结束若计划对应的活没做完(证据:未完成 todo,或批准后再无完成性事件)→ 候选:**计划标题 = objective 草稿,计划正文 = 备注**。

**结构·todo 锚定 Query(片 6b,零模型成本)**:todo 不逐条成候选;相邻 `todo/write` 整表快照差分,**新增条目锚定到它前面最近的一条人类消息**(插件/工具来源事件跳过 —— 纯日志连接)。会话存在未完成条目且无 goal/已批计划时 → 候选:**objective 草稿 = 触发该 todo 链的用户原话**,未完成条目列入备注。锚定是结构启发式(最近人类消息)而非因果判定,人确认兜底。若该会话持有某任务,未完 todo 同时并入该任务的候选备注。

**兜底·总结档(片 6c,一次模型调用)**:无 goal、未走计划模式、也没写 todo 的会话,静默过 `idleHours` 后起一次总结会话(走 §4 的限流与配额 probe),按 §2 三必要条件判定:**全满足才产候选(objective + acceptance 必填),否则记"无任务"水位**。不再要求人挑会话;看板上保留手动入口(对未到闲置时间的会话立即可抽)。

## 7. 进度同步:会话里的活自动回流台账

出生之后,进度回流现状全靠模型自觉(`task_update`/`task_report`),会话干了一下午不汇报,台账就撒谎("闲置 3 天"而活干了一半)。与出生同一思路:会话日志里已有进度证据,让它们自动回流。**只有持有会话的信号回流**;陌生会话依法不能动别人的任务,子任务各有各的持有者,父任务闲置已按子树取新鲜值。

**第一层·活跃度(零写入,展示侧连接)**:闲置显示取 `max(台账 workedAt, 持有会话最后事件时间)` —— 持有会话在动 = 这条线没被搁下。不产生账本事件,不与模型自身的 task_update 撞版本号(CAS)。持有会话不在进程内(已死/未运行)时退回台账 workedAt。

**第二层·上下文包增量(回合末一次写入)**:持有会话每回合结束,本回合若有 **todo 差分**(勾选推进)或 goal 变化,自动追加一条 progress 进上下文包,actor 记为该持有会话(权限矩阵天然满足)。纯闲聊回合不写 —— 包的每行都要有内容;沿既有字节上限截断。与模型自己的 task_update 撞 revision 时:同步侧读最新 revision 重试一次,再失败则丢弃(下回合差分自然补上,进度不丢)。

**第三层·状态镜像(goal 相变)**:
- goal **blocked** 且非配额码 → 自动将任务置 blocked,卡点原因带入(面板"阻塞置顶"立即生效)。配额码跳过 —— 那是 task-quota 的职责,避免双重处理。
- goal **complete** → 自动提交进"待验收",completion note 注明"由 goal 完成自动提交,请按验收标准人工裁决"。人仍是终审。

headless 一次性会话在 `session/disposed` 时做最终一次第二层冲刷。巡检职责不变:观察**非持有**任务的全局兜底。

## 8. 人面(6a 已落地)

- 看板:五列之外加**「待确认」列**,入口带数量角标;候选卡可编辑 objective/acceptance 后晋升,或忽略;被来源会话自动失效(superseded)的候选折叠显示。
- 命令:`/task candidates`、`/task promote <候选id前缀> [新目标 ::] <验收标准>`、`/task ignore <候选id前缀>`。
- 晋升 = 普通任务 create,任务的来源字段记下候选与源会话,源会话计入该任务 sessionIds。
- 巡检不读候选(指令与 inventory 均不含);候选列自身有角标即提醒。

## 10. 开放问题(定稿前定)

1. 候选老化:长期未处理(如 30 天)的候选清理还是保留?倾向保留 + 排序置底。
2. goal 跨会话 resume 是否保持同一 goal id:决定 goal 档去重键;不可靠则退化为"同 sessionId 去重"。
3. 自动晋升开关:倾向**不做** —— 人确认是产品立场("待验收必须人确认"的同族纪律)。
4. 一个会话多条未完 todo 链(用户连发两个无关请求各留未完步骤):v1 合并一条取最近链;按链拆多条看真实使用是否出现。
5. todo 锚定在长会话可能锚偏(模型补写早前工作的 todo):接受为已知误差;常见再考虑按请求头对齐。
6. 总结档读整段会话记录的上下文成本:长会话截断策略(近 N 条 + goal/plan/todo 事件全量)在 6c 实现时定。
7. superseded 的"完成证据"对总结档候选只能靠再次总结判定:仅在新活动后触发,成本有界。
8. goal 镜像的误配风险:会话持有任务后又改 goal 做别的,goal complete 会误提交该任务。候选缓解:仅镜像**认领之后创建/编辑的 goal**;真实使用出现再收紧。
9. 活跃度连接的宽纵:持有会话闲聊也刷"不闲置"。接受 —— 会话还活着就该由它负责(不做就释放);巡检仍从内容面说出真相。
10. 回合末的定义与信号:以 agent 回合结束事件为准,实现时对齐 dsh-agent-loop 的事件面;若事件粒度不足,退化为"静默短窗(如 90 秒无新事件)聚合一次"。
