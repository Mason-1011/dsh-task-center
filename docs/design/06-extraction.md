# 06 抽取层:任务从已有记录出生

状态:已定稿;实现中——片 6a/6b/6c/7a/7b/7c、存量回灌(§8)、验收档(§5)与打回回流(§5)已落地(2026-08-19,见 §10 切分表),§7 三层齐;后续按 04-plan 推进。前置判断:任务不应该是独立于 plan / goal / 普通对话之外的东西,而应能从 dsh 已有的功能与记录中抽取;抽取要自动化、无感,同时要有严格的"什么是任务"判据防噪声。

## 1. 问题:出生通道与原始记录脱节

现状里任务只有两条出生通道,都要人驱动:`/task create`(人类面)与 `task_create`(模型面)。而 dsh 会话日志里**已经**记着任务形状的东西:

| dsh 已有记录 | 事件 | 内容 | 缺什么 |
|---|---|---|---|
| goal(目标) | `goal/change`,全量快照 | objective、phase(active/paused/blocked/complete)、blocker、轮次 | 跨会话;验收标准;人的裁决 |
| plan(计划模式) | `exit_plan_mode` 工具调用,必填 `plan` 参数 | **完整计划 markdown,以 # 标题开头**;经人类精确批准 | 跨会话;验收标准同款 |
| todo(待办) | `todo/write`,整表快照 | 步骤文本 + 三态勾选;可锚定到触发它的人类消息 | 目标级视角;一切跨会话字段 |
| 普通对话 | `user/message` 等 | 用户说过的每一句"要做 X" | 一切结构 |

这些记录的共同点:**只属于单个会话,会话停了就停在那里,没有机制负责跨会话追问**。而"被遗忘"恰恰发生在人离开之后。登记是纪律,纪律靠不住,台账于是常年是空的,看管价值无从发生。仓库已有一次性先例 `c86ba75`(cc-transcript 导入);本设计把它一般化为**常驻、自动、无感的抽取**。

## 2. 任务的抽取判据(防噪声的定义)

抽取自动化的前提是判据严格。一条记录要成为候选,必须**同时**满足三必要条件:

1. **可命名的结果**:能用一句话说出"做成之后世界里多了什么"。objective 是**结果**不是动作("支持暗色模式"✓,"看看暗色模式"✗)。
2. **可判定的完成**:能写出验收标准 —— 一条事后可检查的判据。写不出完成判据的(纯讨论、开放探索、感受表达)不是任务。
3. **未完成且需要后续工作**:本会话内已做完、已回答的,不抽。做完的事是历史,不是任务。

结构档(goal / 已批计划 / todo 链)天然满足三条件:goal 创建即带 objective、未完 phase;计划有标题与步骤且经人批准;todo 链锚定的是用户原话。**总结档(模型抽取)必须三条全填才准产候选:objective、acceptance 都要写得出,acceptance 填不出 → 返回"无任务"。宁缺毋滥。**

反例与正例(总结档提示词内置):

| 会话里的事 | 判定 |
|---|---|
| "为什么这里报错?" 已解答 | 无任务:已回答 |
| "聊聊这个架构怎么样" | 无任务:无结果命名、无完成判据 |
| "帮我加暗色模式" 没做完 | 任务(objective: 支持暗色模式;acceptance: 切换后全部界面生效) |
| "以后有空把首屏优化一下" | 任务(objective: 首屏 < 1s;acceptance 可写;未做)—— 搁置的意图正是本产品目标 |

去重:总结档在抽取时拿到现有任务与候选的 objective 列表,判定为重复的不产候选(可标注关联既有任务)。

## 3. 原则:两层,各司其职

纯投影(任务完全从会话日志实时算出)不可行:持有者、闲置时钟、唤醒规则、验收裁决是**跨会话事实**,不属于任何会话日志,只读视图装不下它们,也没有地方写回。因此:

```
抽取层(新,读):自动扫描会话 → 派生"候选" → 人确认晋升 → 进台账
台账层(已有,写):状态机 / 持有 / workedAt / 唤醒 / 巡检 / 验收 —— 跨会话唯一权威
```

- 抽取层是投影,不产生权威状态;它的产出只有候选。
- 台账层职责不变,仍以台账为唯一输入(巡检、唤醒、闲置都不读会话日志)。
- `task_create` 定位收窄:只剩干活途中分解父任务一个用途(`parent_task_id`),工具描述随之更新。

## 4. 触发:结构信号即时,纯对话才等闲置

**双触发(2026-08-18 修订)**:

- **结构档(goal/计划/todo)即时触发**:goal 被设置、计划被批准、todo 被写入的**那一刻**就走一次结构抽取——这是对工作的显式声明,不存在"被搁下"的歧义,等闲置毫无意义;结构抽取零模型成本,即时出生零花费;噪声闸门是「待确认」里的人工晋升,不是闲置。挂载时对所有存活会话做一次启动结构扫(恢复的历史同样即时出生)。goal 当场做完 → 完成证据同样即时把 pending 候选 superseded(设了又做完,候选闪现后转已失效,人可翻看)。
- **兜底总结档才吃闲置门**:会话静默超过 `idleHours`(默认 3 小时,config 可调)——"3 小时没人说话"区分了"人还在,只是去倒杯水"与"这条线被搁下了";这个问题只对**无结构信号**的纯对话会话存在。`session/disposed`(会话明确关闭,含 headless 一次性会话)立即触发,不等闲置。
- **验收档读即时、生靠搁置门(2026-08-19)**:goal 被标记 complete 的那一刻,即时结构通道**只读不生**——完成落地时人还没来得及回应,判不出"有没有人验收过";水位留在后面,由闲置/处置/史扫三道搁置门看定局后的全量日志:完成之后没有任何人类消息(`source.kind === 'user'`,任何后来的人类一行都算"人回来过、有机会表态")才生为待验收任务,处置会话(日志已闭合,永远不会再有人回应)立即生。

- 活动/水位跟踪:进程内订阅 `session/event` 记每个会话的最后事件时间;重启后从持久化日志做一次启动扫描(task-reaper 同款模式)。闲置时钟锚定到最后一条**持久**事件——水位播种跳过 store 附着日志时补的 `session/end-seed` 簿记标记(附着不是会话活动),恢复的会话开机即可判闲置。
- 幂等:每个会话记录"已抽取水位"(最后抽取时的活动位置)。会话有**新活动**才可能再次抽取;静默着的老会话不重复花钱。
- 每轮 tick 限制总结会话数量(防止开机/久置后突发一堆模型调用),超额顺延;配额墙复用 task-wake 的 probe 推迟模式。
- 结构档(goal/计划/todo)先跑:**零模型成本**;有结构信号就不起总结会话。总结会话只在无结构信号时兜底。即时结构通道只做结构抽取:返回的总结请求被忽略,模型花费永远只经闲置/处置两条门。

## 5. 候选:新的轻实体族

- **不进任务状态机**。候选动词:`promote`(晋升为任务)、`ignore`(忽略,终态)、`superseded`(自动:来源会话后来把事做完了 —— goal complete / todo 全勾 / 后续对话明确收尾 —— 候选自动标记失效,人仍可翻看)。
- **进台账事件流**(与 projects 同模式的新实体族,同一 fold 聚合返回):重启可恢复、看板可读、与任务同源持久化。
- 记录字段:候选 id、来源(`sessionId` + 事件引用)、objective 草稿、acceptance 草稿(结构档留空由人补)、备注(blocker / 未完 todo / 计划正文)、创建与水位时间。
- **去重(v1 实现)**:去重键是完整来源三元组(sessionId + tier + key);同源候选**任一状态**(含已忽略/已失效)存在即不再产,不刷新时间戳。goal id 跨会话不复用,故跨会话同主题会各产一条——是否升级为跨会话键随开放问题 2 的真实数据定。同会话单候选(见 §11.4)。
- **忽略语义**:同源任一状态即去重 ⇒ 忽略天然对该来源永久;「已忽略后再现」标记随之不需要(未实现;若将来放开同源再现再补)。

## 6. 抽取规则:常驻结构档 + 兜底总结档

同一会话一次抽取,出生按结构优先级:**goal > 已批计划 > todo 锚定 Query** —— 三者常是同一件事的三个影子,不重复出生(有未完 goal 时计划/todo 档不出生,有已批计划时 todo 档不出生;goal 档逐 goal 出生,v1 可同会话多条)。**撤销(6b 落地)与出生无关**:任一档出现"做完了"的正证据(goal 完结/清除、todo 全勾或清空),该档 pending 的候选即自动 superseded。

**结构·goal(片 6a,零模型成本)**:fold 该会话的 goal;phase 为 active / paused / blocked(非 complete、非已 clear)→ 候选。objective 直取 goal.objective,blocker 写入备注。

**结构·已批计划(片 6b,已实现,零模型成本)**:计划全文躺在 `exit_plan_mode` 的必填 `plan` 参数里,批准走 `ctx.userQuestions` 精确批准 —— 不需要模型总结。判定"已批"(落地):`exit_plan_mode` 的 `tool/call` 与**无 error 的 `tool/result`** 配对 —— 拒绝/取消都在工具内抛错、结果带 error,`/plan off` 根本不发这个调用,因此不依赖滞后一步提交的 `plan/mode` 翻转。做完的判据:最新 todo 快照全勾(或已清空);没做完则产候选(**计划标题 = objective 草稿,计划正文 = 备注**):有未完 todo 即候选;从未写 todo 的,仅当批准后再无任何模型动作(动过手但没跟踪的停滞:v1 无档接手——总结档按 §4"存在结构信号即不启动"的规则不管它,真实使用出现再定归属)。全勾之后,该会话 pending 的计划候选自动 superseded。

**结构·todo 锚定 Query(片 6b,已实现,零模型成本;锚定 2026-08-18 修订)**:todo 不逐条成候选;相邻 `todo/write` 整表快照差分,**新增条目锚定到它前面最近的一条人类消息**(`source.kind === 'user'` 才算人类;插件通知/工具结果跳过 —— 纯日志连接);**该链没有任何前置人类消息时(模型自主开工),退而锚定到最近一条有正文的助手消息**——溯源到产生 todo 的 Query,没有 Query 就溯源到模型的输出。会话存在未完成条目且无 goal/已批计划时 → 候选:**objective 草稿 = 触发该 todo 链的用户原话(取第一非空行)**,未完成条目列入备注;origin key = 锚定消息的 seq(新链 = 新候选)。锚定是结构启发式(最近人类消息)而非因果判定,人确认兜底。多链取最近链(v1,§11.4);全勾后该会话 pending 的 todo 候选自动 superseded。(未完 todo 不静态并入所持任务备注:7b 以回合末差分进度行替代——记变化,不抄清单,包的每行都有内容。)

**兜底·总结档(片 6c,已实现,一次模型调用)**:无 goal、未走计划模式、也没写 todo、且至少有一条人类消息的会话,静默过 `idleHours`(或 `session/disposed`)后走一次总结会话:先以 maxTokens=1 探测 `agent` 路由配额(QUOTA 阳性即顺延、按平台延时退避;探测失败不挡),再受每轮 `summariesPerTick` 上限约束(超额的活会话水位不推进、下轮重试;处置会话的请求被墙则入队,由后续 tick 重试——它已不在扫描列表里,队就是它唯一的载体)。提示词内置 §2 三必要条件与反例正例表、现有任务与候选的 objective 去重清单、近 `transcriptEvents` 条 surface 消息(人类消息与模型回答;插件通知/工具结果不算),要求只回一个 JSON:**objective + acceptance 必填,否则 `{"none": 原因}`**;解析失败、字段留空一律按无任务处理(宁缺毋滥),一次活动至多花一次总结。origin key 固定为 `summary`(同会话单候选,§11.4):任务判定不重复出生,`none` 判定把该会话 pending 的总结候选自动 superseded——§11.7 的落地形态。

**打回回流(reject 推回来源会话,2026-08-19)**:验收出生被人在看板打回后,理由不能停在台账里——干活的对话必须知道为什么被打回。`task/changed` 载荷携带提交变更原文 `mutation`(理由等字段不在任何视图投影里),reject 且 origin 为验收出生时,抽取层把打回推回来源会话:已搁置的会话从持久层恢复(`agents.resume`)、活的直接复用(`agents.get`);恢复的 setup 按会话日志记录的预设加入名册组合(`resolveSessionPreset` → `agentPresets.mount`)——api-proxy 为它开的每个会话都装这道加入,程序化 resume 不装则 agent 只剩宿主层工具,重做回合对文件/命令调用一律 `unknown tool`;先**代它认领**任务(仅无持有者轮:fold 打回保留持有者,持有轮的重做本就是该会话的,跳过认领;claim 回 active,上下文包注入先于消息),再以 `source.kind === 'user'` 的用户消息送入打回理由——看板是那个人的另一张嘴;推送文本指路 `task_report` 重交。驱动一个回合后释放句柄,消息永留日志(路由失败也只是把裁决停在日志里等下次打开)。重做完成走既有纪律:task_report 提交,或重下的 goal 其完成经 7c 镜像提交(被打回的 goal 本身已 complete 终态,不能也不需要回退)。两道配套:fold 的"已回应"序再加**提交回执**(镜像已把完成递进台账,验收档只捞从未进账的完成);回合结算按会话串行成链,处置终读先等链落定再折日志(镜像提交的回执已在日志里,不与终读赛跑)。**开机对账**:监听器只听得见活提交——裁决落在插件不在场时(版本切换前的打回、提交与推送之间进程崩溃)就永远送不到;裁决本身在账本里持久,送达却不是。推送成功必经认领把任务带出 todo,所以「验收出生 + 无持有者 todo + 账本末变更为 reject」恰是未送达的裁决;启动时按账本历史(`changes(taskId)` 读——理由等字段只在变更原文里)重推,路由失败任务原样,下次启动再试。

**验收档(goal 完成而无人回应,2026-08-19,零模型成本)**:7c 镜像把"会话持有任务、goal 完成"提交进待验收,但**没有持有任务的会话**里模型自己宣告做完的 goal(如贪吃蛇:做完即止,人从未回应)此前无声消失——模型的"做完了"是主张不是裁决。fold 规则:goal 最新变更 phase 为 complete 且其后**没有任何人类消息**即为"未验收完成";后续 edit/resume/clear 把它移出 standing(未完 goal 仍是候选档的事),人回复后的重新完成再次计入。出生形态:**直接进任务「待验收」**(用户定案),不走候选——工作真实已完成,无需再确认"要不要做";域动词 `acceptanceCreate`(仅 source):无持有者、acceptance 留空、contextPack 首行 `SUBMITTED: 完成说明`(注明由抽取层提交、请人工验收),origin 记 `{sessionId, goalId}` 同源任一状态不重复出生。人的裁决:approve → done;reject → 回**可认领的 todo**(无持有者的出生无处退回 active——unheld active 无人能认领;有持有者的提交退回持有者重做不变)。无撤销句柄:工作真实已完成,不自动弃置。

## 7. 进度同步:会话里的活自动回流台账

出生之后,进度回流现状全靠模型自觉(`task_update`/`task_report`),会话干了一下午不汇报,台账就撒谎("闲置 3 天"而活干了一半)。与出生同一思路:会话日志里已有进度证据,让它们自动回流。**只有持有会话的信号回流**;陌生会话依法不能动别人的任务,子任务各有各的持有者,父任务闲置已按子树取新鲜值。

**第一层·活跃度(零写入,展示侧连接,片 7a 已实现)**:闲置显示取 `max(台账 workedAt, 持有会话最后事件时间)` —— 持有会话在动 = 这条线没被搁下。不产生账本事件,不与模型自身的 task_update 撞版本号(CAS)。持有会话不在进程内(已死/未运行)时退回台账 workedAt。`session/end-seed` 是挂载时打的账面标记,不算活动 —— 从盘上恢复的会话不能因为被挂载就显得新鲜。落地归属:`effectiveIdle` 的第 4 参 `holderActivity` 连接器在 `@task-center/task`(`idle.ts`,`lastSessionActivity` 跳过 end-seed),面板(command-task)与看板(task-web)各自经 `ctx.sessions.get` 提供连接 —— 纯展示 join,不进 task-source(§10 归属段的修订)。

**第二层·上下文包增量(回合末一次写入,片 7b 已实现)**:持有会话每回合结束(`turn/end`,完成/中止/任何 reason 同待遇——证据与结局无关),本回合若有 **todo 差分**(勾选推进)或 goal 变化,自动追加一条 progress 进上下文包,actor 记为该持有会话(权限矩阵天然满足)。窗口 = 自上次结算 seq 之后到本回合 turn/end 的闭区间;todo 差分取"窗口前最后一表"对"窗口内最后一表"(窗口内没写 todo 即无差分);goal 变化逐事件渲染,clear 用更早快照报出目标名。行首 `自动回流` 前缀与模型自己的 task_update 汇报区分。纯闲聊回合不写 —— 包的每行都要有内容;沿既有字节上限截断。与模型自己的 task_update 撞 revision 时:同步侧读最新 revision 重试一次,再失败则丢弃(下回合差分自然补上,进度不丢)。结算标记在首个 await 前同步推进,背靠背回合不双结算;首次结算的种子只数**严格早于本次结算回合**的 turn/end——挂载后才结束的回合整回合回流(含挂载前尾巴,补上本进程错过的回流),纯历史回合永不回流。

**第三层·状态镜像(goal 相变,片 7c 已实现)**:与第二层同一窗口、在其后应用:
- goal **blocked** 且非配额码 → 自动将任务置 blocked,卡点原因带入(面板"阻塞置顶"立即生效)。配额码跳过 —— 那是 task-quota 的职责,避免双重处理。
- goal **complete** → 自动提交进"待验收",completion note 注明"由 goal 完成自动提交,请按验收标准人工裁决"。人仍是终审。
- 镜像按**判定性转移**触发:operation 进入 blocked/complete 才算(blocked 中 edit 不重复镜像,resume 不镜像);同 goal 窗口内多次变化取最终相;仅 active 任务镜像(block/submit 的唯一合法源);第二层的 progress 写入在前、会把 blocked 归一化回 active,故"先阻塞后完成"的窗口仍能提交。CAS 同款重试一次再丢——证据行已在 pack 里,状态丢了自己看得见。多 goal 并发于同一任务时按事件序应用,后到者可能撞转换表被丢(v1 已知限制,见 §11)。

headless 一次性会话在 `session/disposed` 时做最终一次第二层冲刷(不写回执——日志已闭合)。巡检职责不变:观察**非持有**任务的全局兜底。

## 8. 存量回灌(装机扫史,2026-08-18)

刚装上插件的人,历史会话全在盘上、不在存活列表里——`ctx.sessions.list()` 只见活会话,启动结构扫永远扫不到存量。挂载后一次**史扫**(detached,不等挂载):经 `sessionPersistence.list()`(可选服务,`ctx.get` 读;没有后端则记日志跳过)枚举全部落盘会话头,逐个 `inspect()` 只读检查,分流入既有的出生/节流管道:

- **跳过四类**:本家族机器会话(id 前缀 `summary-`/`wake-`/`patrol-`,`isMachinerySession` 同时挡即时/闲置/处置/扫史四条路——自家提示词不当源,工作已由回流与巡检进账;回流照常进机器会话,它们持有的任务不受影响)、subagent 子会话(header `origin === 'subagent'`,委派机器——工作经父会话回执进账)、活会话(启动结构扫与闲置扫描的地盘)、已覆盖地(见下)。
- **持久覆盖标记**:每会话"已抽取到哪个 seq"存本插件自己的 storage domain(`task_source` 域 `covered` 表),不在账本事件流——标记是抽取器簿记不是域状态(dsh 投影缓存把检查点放流外的同款先例);重启/重装不重读已覆盖地、不重付总结费。无 storage facility 时退内存标记(测试与最小组合可用;重启重扫但同源去重兜底)。持久优先、内存其次:持久写失败内存不动,下次开机重抽而非静默漏抽。
- **结构档即扫即出生**(零模型成本,goal/计划/todo 史一次到位),结构落定的会话当场覆盖到尾;**纯对话史排队走同一道闲置门**(readyAt = 末事件时间 + `idleHours`,处置请求 readyAt = 0),统一队列由 tick 的 `summariesPerTick` 上限与配额 probe 约束——回灌与日常扫描共用同一节流,装机风暴不成立。队列请求的会话复活(重进存活列表)即作废:活扫描接管,旧快照不再判定。
- **一次性迁移(验收档晚于覆盖标记,2026-08-19)**:验收档启用前各启动已把结构落定的会话覆盖到尾,重启永远不会再读——已覆盖地里的未验收完成(存量贪吃蛇类)永远不会浮出。首扫用 `flags` 表(同域新增 `key→value` 表,版本不动)做一次性迁移:无 `acceptance-births` 标记的启动把已覆盖地重读一遍,**零模型成本**(已覆盖会话的总结早已跑过或本不适用,只有验收出生与搁置中的延迟出生会发生),末事件已过闲置门的当场生、没过的按同一道门入队;跑完落标记,此后永不重读。标记失败不挡扫描本身,下次启动重来(同源去重兜底重复出生)。
- **失败不覆盖、指数退避**:总结会话起不来(路由没配、key 没填;`agent/error` 事件或 whenIdle 拒绝)报 `failed`——覆盖标记不推进,连续失败按 `pollSeconds` 翻倍退避(上限 32 倍轮距),先装后配 key 的场景补配后存量自动流。判定完成但解析不出 verdict(缺失/留空)仍算 `done` 有界消费——宁缺毋滥不变。总结会话一次性:判定读完即 dispose 句柄,注册不累积、同 id 重试不撞(此前失败句柄漏注销会让重试的 create 撞 id、tick 连环抛);**每次尝试现铸新机器会话 id**(尾缀时间戳)——持久层对同 id 但不同 cwd 的创建报碰撞,确定性 id 会撞上失败尝试留下的工件、抛错把排队请求静默丢弃(summarize 抛错一律按 failed 处理,队不丢)。总结会话(与 task-wake 的唤醒/巡检会话)创建时携带 cwd——部署组装的 persona 段渲染 `{{cwd}}`,无 cwd 的机器会话首回合即组装失败(2026-08-18 部署验证发现的真 bug);总结会话锚定来源会话的工作目录,唤醒/巡检锚定进程目录。

## 11. 开放问题(定稿前定)

1. 候选老化:长期未处理(如 30 天)的候选清理还是保留?倾向保留 + 排序置底。
2. goal 跨会话 resume 是否保持同一 goal id:决定 goal 档去重键;不可靠则退化为"同 sessionId 去重"。
3. 自动晋升开关:倾向**不做** —— 人确认是产品立场("待验收必须人确认"的同族纪律)。
4. 一个会话多条未完 todo 链(用户连发两个无关请求各留未完步骤):v1 合并一条取最近链;按链拆多条看真实使用是否出现。
5. todo 锚定在长会话可能锚偏(模型补写早前工作的 todo):接受为已知误差;常见再考虑按请求头对齐。
6. 总结档读整段会话记录的上下文成本——已定(6c):截断为近 `transcriptEvents` 条 surface 消息(人类消息与模型回答);"goal/plan/todo 事件全量"被更强规则取代——存在任一结构信号即不启动总结档,截断只发生在纯对话会话上。
7. superseded 的"完成证据"对总结档候选只能靠再次总结判定:仅在新活动后触发,成本有界——6c 落地:origin key 固定 `summary`,新活动后的 `none` 判定即 supersede 该会话 pending 的总结候选。
8. goal 镜像的误配风险:会话持有任务后又改 goal 做别的,goal complete 会误提交该任务。候选缓解:仅镜像**认领之后创建/编辑的 goal**;真实使用出现再收紧。
9. 活跃度连接的宽纵:持有会话闲聊也刷"不闲置"。接受 —— 会话还活着就该由它负责(不做就释放);巡检仍从内容面说出真相。
10. 回合末的定义与信号:以 agent 回合结束事件为准,实现时对齐 dsh-agent-loop 的事件面;若事件粒度不足,退化为"静默短窗(如 90 秒无新事件)聚合一次"。
11. 史扫对 fork/resume 子会话(继承父历史前缀)会重复出生父会话已出的候选(去重键含 sessionId);真实使用出现再按 `seedLength` 前缀豁免。
